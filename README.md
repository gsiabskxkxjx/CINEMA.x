# CINEMA X

تطبيق Flutter لمشاهدة الأفلام والمسلسلات العربية والأجنبية، بمشغّل فيديو داخلي، وواجهة عربية (RTL) وإنجليزية، ووضع داكن سينمائي، وخلفية Supabase (مصادقة + قاعدة بيانات + تخزين)، ولوحة إدارة داخل التطبيق للمسؤولين فقط.

> ⚠️ **حالة الاختبار — اقرأ هذا أولاً**
> كُتب الكود في بيئة **لا تحتوي Flutter SDK ولا شبكة**، لذلك:
> - **لم يُشغَّل `flutter analyze` ولا `flutter test` ولا `flutter build`** على هذا الكود. قد تظهر أخطاء تجميع أو تحذيرات صغيرة عند أول بناء (غالباً أسماء معاملات في حزم خارجية مثل media_kit). شغّل `flutter analyze` أولاً وأصلح ما يظهر.
> - **لم يُجرَّب المشغّل على جهاز حقيقي ولا على روابط حقيقية.** منطقه (إعادة المحاولة، الاستئناف، الانتقال للحلقة التالية…) مكتوب بعناية لكنه غير مُختبَر ميدانياً.
> - **ما جرى اختباره فعلياً:** ملفات SQL على PostgreSQL 16 (الجداول، الدوال، RLS، البحث العربي) عبر `supabase/tests/`، وفحوص ثابتة بسكربتات (تطابق مفاتيح الترجمة، حلّ الاستيرادات، توازن الأقواس).
> - ملف CI (`.github/workflows/android.yml`) يشغّل التحليل والاختبارات والبناء تلقائياً، فهو أسرع طريقة لمعرفة الحالة الفعلية بعد رفع المشروع إلى GitHub.

## 3) التشغيل السريع (وضع تجريبي بلا خادم)

```bash
# Linux / macOS / Git-Bash
bash scripts/bootstrap.sh
# Windows PowerShell
./scripts/bootstrap.ps1

flutter run
```

السكربت ينشئ مجلد `android/` (`flutter create`)، ويضيف الصلاحيات واسم التطبيق ورابط العودة (`tool/patch_android.dart`)، ثم يشغّل `flutter pub get` وتوليد الأيقونة.

عند عدم ضبط مفاتيح Supabase يعمل التطبيق **بوضع تجريبي**: أعمال خيالية الأسماء، المفضلة والسجل محفوظان محلياً، ولا توجد حسابات ولا لوحة إدارة. يظهر شريط تنبيه يوضح ذلك.

> **روابط الفيديو التجريبية** تشير إلى أفلام Blender القصيرة المفتوحة (رخصة CC-BY) على خوادم جهات خارجية. **لم أتحقق من توفرها**؛ إن لم تعمل فهذا لا يعني عطلاً في التطبيق. استبدلها بروابط تملك حقوقها من لوحة الإدارة.

## 4) ربط Supabase (الوضع الكامل)

1. أنشئ مشروعاً في Supabase.
2. من **SQL Editor** شغّل الملف `supabase/cinema_x_full.sql` دفعة واحدة. (هو دمج الملفات `01_schema` … `05_seed` ثم `07_tmdb` ثم `08_storage_videos` بالترتيب؛ يمكنك تشغيلها منفصلة بدلاً منه.)
3. اختياري للتجربة فقط: شغّل `supabase/06_demo_content.sql` لإضافة محتوى تجريبي. **لا تشغّله في الإنتاج.**
4. **Authentication → Providers → Email:** اجعل الحد الأدنى لكلمة المرور **8** (الافتراضي 6، والتطبيق يطلب 8). قرّر تفعيل/تعطيل «Confirm email»؛ التطبيق يدعم الحالتين.
5. **Authentication → URL Configuration → Redirect URLs:** أضف
   `io.cinemax.app://login-callback`
   (لازم لرابط استعادة كلمة المرور وتأكيد البريد).
6. انسخ `env/dart_defines.example.json` إلى `env/dart_defines.json` وضع القيم من **Project Settings → API**:
   ```json
   {
     "SUPABASE_URL": "https://YOUR-PROJECT-REF.supabase.co",
     "SUPABASE_ANON_KEY": "YOUR-ANON-OR-PUBLISHABLE-KEY"
   }
   ```
7. شغّل:
   ```bash
   flutter run --dart-define-from-file=env/dart_defines.json
   ```
8. **أنشئ أول مسؤول:** سجّل حساباً من التطبيق، ثم في SQL Editor:
   ```sql
   update public.profiles set role = 'admin' where email = 'you@example.com';
   ```
   سيظهر «لوحة الإدارة» في تبويب «حسابي». لا توجد طريقة لترقية نفسك من داخل التطبيق (مقصود).

> **حالة هذا المستودع:** مشروع Supabase المسمّى `cinema-x` مجهّز فعلاً (الجداول والصلاحيات مطبّقة)، وقيمه العامة في `env/dart_defines.public.json` ويستعملها بناء GitHub Actions تلقائياً. هذه القيم (الرابط + المفتاح العام `sb_publishable_…`) مصمّمة لتكون داخل أي تطبيق؛ الحماية الفعلية هي RLS. للتبديل لمشروعك الخاص عدّل الملف أو أضف أسرار المستودع `SUPABASE_URL` و`SUPABASE_ANON_KEY` فتتقدّم عليه.

### الأمان — ما الذي يوضع في التطبيق وما الذي لا يوضع

- يُوضع في التطبيق **anon / publishable key فقط**، وهو مصمَّم ليكون عاماً.
- **لا تضع أبداً مفتاح `service_role`** في التطبيق أو في `dart_defines.json` أو في Git.
- ملف `env/dart_defines.json` مُدرج في `.gitignore`.
- الحماية الحقيقية في **RLS على الخادم**، وليس في إخفاء الأزرار:
  - جدول `video_sources` مقروء للمسؤول فقط؛ تصل روابط البث للمستخدم فقط عبر الدالة `get_playback_sources` التي تتحقق من تسجيل الدخول وعدم الحظر والاشتراك (Premium) إن كانت الاشتراكات مفعّلة.
  - المشغّل **لا يعرض روابط البث** للمستخدم في الواجهة. (لكن أي مستخدم مسجّل مصرّح له بالمشاهدة يستطيع تقنياً التقاط الرابط من حركة الشبكة؛ لا يمكن لأي تطبيق منع ذلك تماماً. للحماية الأقوى استخدم روابط موقّعة قصيرة العمر من مزوّد الفيديو/CDN.)
  - تغيير `role` و`is_blocked` و`email` في `profiles` يمنعه مشغّل (Trigger) لغير المسؤولين.
  - جدول `app_settings` **مقروء علناً** (حتى قبل تسجيل الدخول)؛ لا تضع فيه أسراراً.

## 5) إدارة المحتوى (لوحة الإدارة)

حسابي → لوحة الإدارة:

- **الأفلام / المسلسلات:** إضافة وتعديل وحذف وإخفاء. كل عمل: عناوين عربي/إنجليزي، قصة، بوستر وخلفية (رفع صورة أو رابط)، سنة، تصنيف عمري، بلد، لغة، جودة، تقييم، مدة، مخرج، ممثلون، تصنيفات، لغات الترجمة، نافذة تخطّي المقدمة، «مميّز»، «Premium».
- **المسلسلات:** المواسم ثم الحلقات (رقم، عنوان، وصف، مدة، صورة، مقدمة)، ولكل حلقة روابط وترجمات مستقلة.
- **روابط الفيديو:** mp4 / hls / dash مع الجودة والتسمية والترتيب. زر **+** يعطيك خيارين: *من رابط*، أو *رفع من المعرض* (انظر القسم أدناه). **الترجمات:** رابط SRT أو VTT مع رمز اللغة. (رفع ملف الترجمة من الجهاز **غير مُنفَّذ**؛ الترجمات تُضاف بالرابط. حاوية التخزين `subtitles` موجودة إن أردت الرفع يدوياً من لوحة Supabase.)
- **الفئات والتصنيفات:** الصفوف التي تظهر في الرئيسية، وشكل العرض (عمودي/أفقي).
- **المستخدمون:** بحث، ترقية/إلغاء مسؤول، حظر/إلغاء حظر.
- **المحتوى المميّز:** ترتيب بانر الرئيسية.
- **إعدادات التطبيق:** وضع الصيانة ورسالته، بريد الدعم، تفعيل الاشتراكات.
- **الإحصاءات:** المستخدمون، الحلقات، المشاهدات (إجمالي و7 أيام)، الأكثر مشاهدة.
- **استيراد من TMDB:** يجلب البوسترات والتفاصيل لصفوف الصفحة الرئيسية (انظر 5-ب).

### 5-ب) استيراد البوسترات والتفاصيل من TMDB

يجلب حتى 100 عمل لكل صف (أكشن، رعب، خيال علمي، كوميديا، أفلام عربية/أجنبية، مسلسلات عربية/أجنبية، أنمي): العنوان بالعربية والإنجليزية، الملخص، البوستر والخلفية، السنة، التقييم، المدة، الأنواع، وأول 8 ممثلين. **لا يجلب أي فيديو**؛ الأعمال المستوردة بلا رابط تشغيل حتى تضيف أنت رابطاً تملكه أو مرخّصاً لك (لوحة الإدارة ← الأفلام/المسلسلات ← روابط الفيديو).

1. سجّل في [themoviedb.org](https://www.themoviedb.org) واطلب مفتاح API (الخطة المجانية، استخدام غير تجاري). انسخ **API Key** (v3).
2. خزّنه **على الخادم فقط**: لوحة Supabase ← Edge Functions ← Secrets ← أضف `TMDB_API_KEY`. لا تضعه في التطبيق ولا في المستودع ولا في `app_settings`.
3. شغّل `supabase/07_tmdb.sql` (أعمدة `tmdb_id` لمنع التكرار) وانشر الدالة `supabase/functions/tmdb-import/index.ts` (باسم `tmdb-import`، مع `verify_jwt` معطّلاً لأن الدالة تتحقق بنفسها من أنك مسؤول).
4. من التطبيق: لوحة الإدارة ← **استيراد من TMDB** ← «استيراد كل الصفوف».

ملاحظات: إعادة التشغيل آمنة (تحدّث نفس العمل حسب `tmdb_id` ولا تكرّره ولا تلمس «مميّز/Premium/النشر/المشاهدات»). الصور تبقى على `image.tmdb.org` (روابط فقط). شروط TMDB: الاستخدام غير التجاري في الخطة المجانية، وإسناد ظاهر (موجود في «حول التطبيق»)، وتجديد البيانات المخزّنة دورياً (`tmdb_synced_at` يوضّح آخر مزامنة). المسلسلات تُستورد بلا مواسم/حلقات.

### 5-ج) رفع فيديو من معرض الهاتف (اختياري)

من لوحة الإدارة → فيلم/حلقة → روابط الفيديو → **+** → «رفع من المعرض». يظهر شريط تقدّم مع زر إلغاء، وعند الانتهاء يُنشأ مصدر تلقائياً بنوع mp4 يشير إلى الملف.

1. شغّل `supabase/08_storage_videos.sql` (أو الملف الكامل). ينشئ حاوية `videos` ويقصر الرفع والحذف على المسؤول.
2. **الحدود (مهمة):**
   - الخطة المجانية في Supabase: **50 MB للملف و1 GB للتخزين كله**، ولا يمكن رفع هذا الحد. تكفي لمقاطع قصيرة أو تجارب، **لا لأفلام كاملة**.
   - الخطة Pro ترفع الحدّ (من Storage → Settings، ثم عدّل `file_size_limit` للحاوية و`app_settings.max_upload_mb`). لكن الملفات الكبيرة جداً تحتاج رفعاً قابلاً للاستئناف (TUS) وهو **غير مُنفَّذ** في التطبيق، فالرفع الحالي طلب واحد ينجح فقط إذا ثبت الاتصال.
   - للأفلام الكاملة الأفضل استضافة فيديو مخصصة (Bunny Stream / Cloudflare Stream / Mux) ثم لصق رابطها بخيار «من رابط».
3. **الأمان:** الحاوية عامة بأسماء عشوائية. الروابط لا تصل المستخدمين إلا عبر دالة التشغيل `get_playback_sources`، لكن من يحصل على رابط ملف يستطيع فتحه مباشرة، فقيد Premium لا يحمي الملف نفسه إذا تسرّب رابطه.
4. حذف المصدر من اللوحة يحذف الملف المرفوع أيضاً. أمّا حذف **فيلم أو حلقة كاملة** فيحذف صفوف المصادر فقط ويبقي الملفات في التخزين؛ احذف المصدر أولاً أو نظّف الحاوية من لوحة Supabase.
5. ارفع فقط ما تملك حقوقه أو مرخّصاً لك.

## 6) المشغّل: ما يدعمه وحدوده

- الصيغ: MP4، HLS، DASH (حسب ما تدعمه libmpv على الجهاز).
- **جودات HLS/DASH:** تظهر في قائمة الجودة **فقط إذا كان الـ manifest نفسه يعرض عدة مستويات**. للروابط MP4 المنفصلة تُضاف كل جودة كمصدر مستقل من لوحة الإدارة.
- الترجمة: SRT/VTT من رابط، والمضمّنة في الملف إن وُجدت.
- يحفظ التقدّم كل 15 ثانية وعند الإيقاف والخروج وتبديل الحلقة، ويُسجَّل المشاهدة بعد 10 ثوانٍ من التشغيل.
- عند الانقطاع: إعادة محاولة (3 مرات مع تأخير متزايد) ثم تبديل تلقائي لمصدر آخر ثم رسالة خطأ عربية مع زر إعادة المحاولة. لا يجب أن ينهار التطبيق بسبب فيديو معطّل.
- **HTTP غير المشفّر:** أندرويد الحديث يمنع الروابط `http://`. استخدم `https://` لكل الروابط.

## 7) البناء والنشر

### بناء APK / AAB
```bash
flutter build apk --release --split-per-abi --dart-define-from-file=env/dart_defines.json
flutter build appbundle --release --dart-define-from-file=env/dart_defines.json
```
الناتج: `build/app/outputs/flutter-apk/` و`build/app/outputs/bundle/release/`.

> سكربت `tool/patch_android.dart` يعطّل مهام `lintVital` في Gradle لأن أداة lint تنهار عند فحص كود إضافة image_picker (خطأ داخلي في الأداة وليس في كود التطبيق). لا يؤثر ذلك على الكود الناتج.

### توقيع الإصدار (إلزامي لـ Google Play)
بدون إعداد التوقيع يُوقَّع البناء بمفتاح التطوير ولن يقبله Google Play. اتبع `android_templates/README.txt` (إنشاء مفتاح `.jks`، ملف `key.properties`، ومقطع `build.gradle` المناسب لإصدار Flutter عندك). **احتفظ بنسخة احتياطية من المفتاح وكلمات مروره؛ فقدانه يمنعك من تحديث التطبيق.**

### البناء عبر GitHub Actions
ارفع المشروع إلى GitHub، أضف Secrets باسم `SUPABASE_URL` و`SUPABASE_ANON_KEY`، ثم شغّل **Actions → Android build**. يحلّل ويختبر ويبني APK و AAB ويرفعها كـ Artifacts. (البناء هناك غير موقَّع للإنتاج ما لم تضف أسرار التوقيع.)

### قائمة جاهزية Google Play
- [ ] توقيع الإصدار + نسخة احتياطية للمفتاح
- [ ] تغيير معرّف الحزمة `com.cinemax.cinema_x` إن لزم (قبل أول نشر؛ لا يمكن تغييره بعده)
- [ ] سياسة خصوصية منشورة على رابط عام (التطبيق يجمع بريداً وسجل مشاهدة)
- [ ] نموذج «Data safety» في Play Console
- [ ] تصنيف المحتوى (Content rating) وتقييم عمري مناسب
- [ ] **توثيق حقوق المحتوى:** أنت المسؤول عن امتلاك أو ترخيص كل ما يُعرض (القسم 10)
- [ ] لقطات شاشة وأيقونة 512×512 ووصف المتجر
- [ ] اختبار على أجهزة حقيقية (شبكة ضعيفة، قطع الاتصال، تدوير الشاشة، أندرويد 8 فما فوق)
- [ ] تشغيل `flutter analyze` و`flutter test` بلا أخطاء

## 9) الاشتراكات والدفع — ما هو موجود وما ليس موجوداً

موجود: جداول الباقات `subscription_plans` (مجاني/Premium، شهري/سنوي) و`subscriptions` و`payments` و`user_devices`، ودوال `current_plan` و`has_active_premium`، وصفحة عرض الباقة، وتطبيق «Premium» على الخادم داخل `get_playback_sources` عند تفعيل الاشتراكات من إعدادات التطبيق.

**حد الأجهزة غير مُطبَّق فعلياً:** التطبيق يسجّل الجهاز عبر `register_device` والدالة ترمي `device_limit_reached` عند التجاوز، لكن التطبيق حالياً يتجاهل هذا الخطأ ولا يمنع البث. إن احتجت فرضه فعلياً فاربطه بـ `get_playback_sources` وبشاشة «إدارة الأجهزة».

**غير موجود:** أي مزوّد دفع (Google Play Billing، Stripe، …) أو زر شراء أو تحقّق من إيصالات. لا يوجد نظام اشتراك عامل. لتشغيله فعلياً يلزمك:
1. حساب مزوّد دفع حقيقي. للمحتوى الرقمي داخل تطبيق Google Play عادةً يلزم **Google Play Billing**.
2. دالة خادم (Supabase Edge Function) تتحقق من الإيصال/الـ webhook وتكتب في `subscriptions` و`payments` بمفتاح الخدمة **على الخادم فقط**.
3. شاشة شراء في التطبيق.

حتى ذلك الحين اترك «تفعيل الاشتراكات» مغلقاً.

## 10) حقوق المحتوى (مهم قانونياً)

CINEMA X **منصّة عرض فقط ولا تستضيف أي محتوى**، ولا يتضمن المشروع أي روابط أفلام أو مسلسلات مقرصنة، ولن يُضاف شيء منها. بيانات البوسترات والتفاصيل المستوردة من TMDB وصفية فقط. *This product uses the TMDB API but is not endorsed or certified by TMDB.* لوحة الإدارة تسمح بإضافة روابط **تملك حقوقها أو مرخّصة لك قانونياً فقط**. نشر محتوى مقرصن يعرّضك لإزالة التطبيق من المتجر ولمساءلة قانونية.

## 11) الخدمات الخارجية والتكاليف

| الخدمة | لماذا | ملاحظة |
|---|---|---|
| Supabase | المصادقة، قاعدة البيانات، تخزين الصور | يوجد مستوى مجاني محدود (مساحة وعرض نطاق) |
| استضافة الفيديو / CDN | تخزين وبثّ الملفات | **غير مضمّنة.** أنت من يوفّرها لمحتواك المرخّص (Cloudflare R2/Stream، Bunny، S3+CloudFront…). البث يستهلك عرض نطاق كبيراً وهو عادةً أكبر تكلفة |

| Google Play Console | النشر | رسوم تسجيل لمرة واحدة |

## 13) حدود معروفة

- لم يُبنَ ولم يُحلَّل الكود بـ Flutter بعد (انظر أعلى الملف).
- رفع ملفات الترجمة غير مُنفَّذ (بالرابط فقط). رفع الفيديو من المعرض محدود بحدّ تخزين Supabase ولا يدعم الاستئناف (القسم أعلاه).
- iOS: البنية جاهزة (لا كود خاص بأندرويد في طبقة Dart)، لكن لم يُنشأ مجلد `ios/` ولم يُجرَّب. أضفه بـ `flutter create --platforms=ios .` وأضف رابط العودة في Info.plist.
- لا إشعارات دفع، ولا تحميل للمشاهدة دون اتصال، ولا Chromecast.
- الاشتراكات بنية فقط (القسم 9).
- الأعمال التجريبية خيالية، وروابط فيديوهاتها لم يُتحقَّق منها.
